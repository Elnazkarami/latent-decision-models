# ds002158 EEG: alignment, in-scanner cleaning and classical decoding (2 subjects)

- **Date:** 2026-11-19
- **Snapshot:** OpenNeuro ds002158 **v1.0.2**
- **Data:** raw BrainVision EEG of **sub-02 and sub-04**, 6 runs each (36 files, 4.13 GB, downloaded with explicit approval; sizes and sha256 in `data/ds002158/eeg_fetch_manifest.json`, not versioned).
- **Machine-readable:** [`reports/ds002158-eeg-preprocess.json`](../reports/ds002158-eeg-preprocess.json) (pairing and QC per run), [`reports/ds002158-eeg-decoding.json`](../reports/ds002158-eeg-decoding.json) (all decoding results).
- **Scope:** a pipeline check and a first neural baseline on two subjects. With n = 2, nothing here is a population claim.

## Summary

| Question | Answer |
| --- | --- |
| Do EEG runs pair with events runs? | **Yes, 12/12**, by marker timing; all `verified` (timing and labels); every run pairs with its same-named events file. |
| Can the in-scanner artifacts be removed? | **Yes.** Gradient power at the 12.5 Hz slice frequency drops ~25- to 1000-fold, heartbeat-locked activity drops 96% (sub-04) and ~80% (sub-02). |
| Does the pipeline recover a known neural signal? | **Yes (positive control).** Response side decodes from response-locked activity (AUC 0.78 / 0.86) and post-response activity (0.94 / 0.99), transfers across subjects (0.67–0.94), and is at chance before the decision. |
| Is objective accuracy decodable? | **After the response, in own decisions:** AUC 0.68 (sub-02), 0.64 (sub-04), p ≤ 0.015. Not before it. |
| Is confidence decodable? (primary) | **No result survives the pre-specified correction.** Best within-subject: sub-04, own decisions, post-decision window, p = 0.03 (Holm 0.18). Cross-subject hints (p ≈ 0.02–0.04) do not survive correction either. |

## Data facts found on download

- **Headers name the original lab files** (`DataFile=s4_run1_09062017.eeg`), not the BIDS names, so MNE cannot open the files as published. `io.brainvision.read_raw` writes a corrected header to a temporary directory and leaves the data untouched.
- 5000 Hz, 64 channels, INT_16; **Ch32 is ECG** but is typed EEG in the header.
- **Synchronised clocks:** `R128` volume triggers are 6400 samples (1.28 s) apart. Seven triggers over the 12 runs deviate by 1–3 samples and return to the grid at the next volume. For sub-04 run-004 (one trigger +2 samples) the artifact was checked directly: subtracting the template at the grid position leaves 45 µV RMS (a normal volume: 43 µV), at the logged position 420 µV. Triggers are therefore snapped to the grid (tolerance 3 samples; larger deviations stop the pipeline).
- **sub-02 run-004:** the recording stops 0.8 s into the last volume (after the last trial). The incomplete volume is dropped.
- The EEG starts ~2 minutes before the scan. Only the scan period is used.

## Pipeline (`ldm ds002158 eeg-preprocess`)

Per run, without using any trial label:

1. **Pairing** of the EEG run with an events run by marker *timing* (`pair_runs`; every events run of the subject is tried, a pairing must match all trials and be unique).
2. **Gradient artifact:** sliding 21-volume average template subtraction (Allen et al. 2000) at 5000 Hz, locked to the volume grid.
3. **Causal** anti-alias low-pass and decimation to 250 Hz.
4. **BCG artifact:** R peaks on the ECG channel (fallback TP10, the authors' choice, if the ECG rate is implausible), 21-beat average template subtraction.
5. **Causal** 1–10 Hz Butterworth band-pass (the authors' band), bad-channel check (robust z of log SD > 3.5: none found), common average reference.
6. **Epochs** locked to the stimulus marker (−0.2 to 1.2 s) and the response marker (−0.6 to 1.0 s). Response latency comes from the markers, not from `events.tsv`.
7. **Epoch rejection** per subject: log peak-to-peak more than 3.5 robust SDs above the subject median, or above 500 µV.

**Why causal filters.** The authors filtered with a zero-phase (two-pass) filter. That spreads activity backwards in time: a test impulse leaks into the samples before it (`tests/test_eeg.py`). Post-response activity could then appear in a "pre-decision" window. Here every filtered sample depends only on the present and past, so a pre-decision feature cannot contain the response. The price is a frequency-dependent delay, which only makes window labels conservative.

**Not done (differs from the authors):** ICA for residual BCG and ocular artifacts, and dipole-based component selection. Residual heartbeat activity is not time-locked to trials and acts as noise.

**Change made before any decoding, documented here:** the initial rejection rule was a fixed 150 µV peak-to-peak threshold. In-scanner epochs have a median peak-to-peak of ~130 µV, so it rejected 31% of sub-04's epochs, mostly because of the mastoid/temporal edge channels (TP9, FT9, FT10). It was replaced by the robust rule above, which uses no labels. With it, 1 of 576 epochs is rejected.

## Decoding (`ldm ds002158 eeg-decode`)

The plan was fixed in [`configs/ds002158_eeg_decoding.yaml`](../configs/ds002158_eeg_decoding.yaml) before any decoding was run.

- **Trials:** valid trials only (author exclusions applied), not rejected, own (active) and observed decisions always analysed separately.
- **Windows** (`datasets.ds002158_eeg.WINDOWS`):
  - **pre-decision:** 0–0.2 s after the stimulus; trials whose response marker comes earlier are dropped (none in valid trials, whose RT ≥ 0.2 s);
  - **response-locked:** −0.2 to +0.1 s around the response;
  - **post-decision:** +0.1 to +0.6 s after the response; ends before the confidence scale (~1.5 s), so it never contains the rating. It does still contain motor execution and its feedback.
- **Features:** mean amplitude per channel in 50 ms bins (63 channels × 4, 6 or 10 bins).
- **Models:** standardisation + L2 logistic regression (AUC) or ridge regression (Spearman r). Regularisation by inner cross-validation within each training fold.
- **Within subject:** leave-one-run-out (6 folds). p-values from 200 permutations of labels *within run*, re-running the whole pipeline (smallest possible p = 0.005).
- **Cross subject:** train on one subject, test on the other; p from 1,000 permutations of the test labels.
- **Primary family:** continuous confidence × 3 windows × 2 conditions, Holm-corrected within each subject.
- **Confidence beyond behavior:** confidence residualised on accuracy, response latency and evidence, with the residualising model fitted on training folds only.

**Reading the scores.** Confidence drifts between runs (run means 0.54–0.69). With leave-one-run-out, a training set's mean then sits on the wrong side of the held-out run's mean, so the pooled held-out correlation is biased negative. The permutation nulls show this (null mean −0.09 to −0.23 for confidence). Compare scores with the null (`null_95`, `p_value`), not with 0. The same effect pushes some AUCs below 0.5.

### Cross subject (train on one, test on the other)

- **Choice side, own decisions:** response-locked AUC 0.69 / 0.67, post-decision 0.80 / 0.94 (all p = 0.001); pre-decision at chance.
- **Confidence:** the uncorrected p < 0.05 cases are own/post-decision (r = 0.18 in both directions, p = 0.03) and observed/pre-decision (r = 0.15 and 0.20, p = 0.04 and 0.02). Holm over the 12 cross-subject confidence tests: all ≥ 0.20.
- **Accuracy and confidence beyond behavior:** no consistent transfer.

## Interpretation

- **The pipeline works.** Lateralised motor activity is recovered within and across subjects, only at and after the response, which is what the window definitions predict. Error-related information appears only after own responses.
- **No reliable confidence signal at n = 2.** The pre-specified primary family has no result surviving correction in either subject. The most consistent hint is own decisions, post-decision window (sub-04 within subject; both cross-subject directions). It sits where accuracy is also decodable, and residualising on accuracy, RT and evidence weakens it (within sub-04: r = −0.12, p = 0.80; cross-subject: r = 0.15 / 0.10, p = 0.06 / 0.14). It should be treated as a hypothesis for the full sample, not a finding.
- **Window semantics:** "post-decision" here means after the committed response, not free of it: the window still holds motor execution (choice side decodes at AUC ≥ 0.94). Nothing decoded post-response is a prospective prediction.

## Recommended before scaling to all subjects

1. **Pre-specify a run-mean-free metric** (per-run Spearman averaged over folds, or centring the target within run on training statistics) to remove the run-drift bias. Not applied here, because it was found after the results were seen.
2. Compare the residual BCG with an ICA or OBS approach on one subject (sub-02's weaker heartbeat detection).
3. Download the remaining subjects' raw EEG: ~2 GB per subject, 33 GB for the other 17 subjects (excluding sub-20). **Needs approval.**

## Reproduce

```bash
pip install -e '.[eeg]'                                      # MNE (optional extra)
ldm ds002158 fetch-eeg --subjects sub-02 sub-04 --dest data/ds002158 --approved-gb 4.2
ldm ds002158 eeg-preprocess --bids-root data/ds002158 --trials data/ds002158_trials.csv \
    --subjects sub-02 sub-04 --out-dir data/derivatives/ldm-eeg \
    --report reports/ds002158-eeg-preprocess.json            # ~3 min
ldm ds002158 eeg-decode --config configs/ds002158_eeg_decoding.yaml \
    --out reports/ds002158-eeg-decoding.json                 # ~10 min on 8 cores
```

`fetch-eeg` refuses to download anything if the selection exceeds `--approved-gb`; `--dry-run` reports the size first.
